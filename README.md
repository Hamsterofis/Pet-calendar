[ НАЗВАНИЕ ПРОЕКТА ]

“Всё о домашних животных”: дневник питомца, ИИ-консультант и карта помощи

[ ПРОБЛЕМНОЕ ПОЛЕ ]

Низкий уровень информированности владельцев: Многие люди заводят питомцев спонтанно и не знают базовых правил ухода (например, необходимость чистки зубов или профилактика стресса). Из-за этого животные часто страдают от заболеваний (зубной камень, ожирение, неврозы), а информация в интернете разрознена и часто недостоверна. Отсутствие координации в помощи бездомным животным: Неравнодушным людям и волонтерам сложно отслеживать места скопления бездомных животных и делиться этой информацией для эффективной помощи (подкормка, отлов, поиск хозяев).

[ ЗАКАЗЧИК / ПОТЕНЦИАЛЬНАЯ АУДИТОРИЯ ]

Владельцы домашних животных (в первую очередь кошек и собак), начинающие владельцы, а также волонтеры и сотрудники приютов.

[ АППАРАТНЫЕ / ПРОГРАММНЫЕ ТРЕБОВАНИЯ ]

Продукт разрабатывается в виде мобильного приложения для операционной системы Android.
*   **Аппаратные требования:** Смартфон на базе Android (версия 8.0 и выше), 2 ГБ оперативной памяти и более, 500 МБ свободного дискового пространства, доступ к сети Интернет (для работы ИИ и карт). Для разработки: ПК (Windows) с 8 ГБ ОЗУ.
*   **Программные требования:** Среда разработки Android Studio (язык Kotlin/Java) или Flutter (язык Dart). Для работы с картами и ИИ требуется доступ к соответствующим API.

[ ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ ]

Программный продукт будет предоставлять следующие возможности:
1. Регистрация и авторизация пользователя (создание личного аккаунта).
2. Добавление питомца в профиль (указание клички, вида, возраста, породы).
3. Ведение календаря ухода (создание событий: кормление, выгул, чистка зубов, визит к врачу).
4. Настройка push-уведомлений (напоминания о предстоящих процедурах).
5. Просмотр статистики по уходу за питомцем (выполненные/пропущенные задачи).
6. Чат с ИИ-консультантом (отправка текстового запроса и получение совета по уходу).
7. Отображение интерактивной карты на экране устройства.
8. Добавление пользовательской метки на карту (с текстовым описанием и геолокацией).
9. Сохранение и загрузка состояния (импорт/экспорт данных календаря и меток).
10. Синхронизация данных (доступ к сохраненным данным после входа с другого устройства).
11. Наличие графического пользовательского интерфейса (UI/UX).

[ ПОХОЖИЕ / АНАЛОГИЧНЫЕ ПРОДУКТЫ ]

Анализ аналогичных программных продуктов показал, что:
1. **Luppy**: Обладает хорошим календарем и ИИ-консультантом, однако не имеет функции карты для помощи бездомным животным.
2. **Pet & Me**: Отлично реализует карту с GPS-координатами для подкормки бездомных, но не имеет полноценного личного дневника ухода за питомцем.
3. **Лапа.AI**: Предлагает мощного ИИ-ветпомощника и напоминания, но интерфейс ориентирован только на здоровье, отсутствуют социальные функции (карта).
4. **PetCare AI**: Имеет красивый интерфейс и трекер здоровья, но является платным продуктом с подпиской и не решает проблему бездомных животных.

[ ИНСТРУМЕНТЫ РАЗРАБОТКИ, ИНФОРМАЦИЯ О БД ]

*   **Инструменты разработки:** В качестве основного фреймворка выбран Flutter (язык Dart) для кроссплатформенности, либо нативный Kotlin (Android Studio).
*   **База данных (БД):** На первом этапе (MVP) будет использоваться встраиваемая реляционная БД **SQLite**. Выбор обоснован тем, что она не требует отдельного сервера, идеально подходит для локального хранения данных календаря на устройстве пользователя и является стандартом для мобильной разработки. В перспективе — подключение облачной **Firebase** (NoSQL) для реализации авторизации и синхронизации карт между устройствами.

[ ЭТАПЫ РАЗРАБОТКИ ]

1. Исследовательский этап: Сбор и анализ данных, формирование базы знаний.
2. Проектирование и UI/UX-дизайн.
3. Разработка базового модуля (Календарь) и развертывание локальной БД.
4. Интеграция ИИ-консультанта (через внешнее API).
5. Интеграция картографического модуля (Яндекс/Google Maps API).
6. Разработка серверной части и настройка синхронизации аккаунтов.
7. Тестирование и отладка (QA), финальная сборка MVP.
8. Подготовка проекта к защите.

[ ВОЗМОЖНЫЕ РИСКИ ]

1. **Технические сложности с интеграцией ИИ-модели:** Лимиты бесплатных API. *Решение:* Использование нескольких альтернативных API (Hugging Face, Groq) и создание локальной базы FAQ на случай сбоя сети.
2. **Сбои в работе картографического модуля:** Задержки на слабых устройствах. *Решение:* Оптимизация кода, отключение тяжелых слоев, использование упрощенной статичной карты.
3. **Нехватка времени (сжатые сроки):** *Решение:* Строгое соблюдение графика, приоритизация функций (если не хватает времени, в первую очередь сдаются Календарь и Базовая карта, ИИ может быть заменен на FAQ).
